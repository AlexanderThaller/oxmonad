= oxmonad architecture
:toc: left

oxmonad is an xmonad-style tiling window manager for Wayland. It is **not** a
compositor: it runs as the window-manager client of
https://codeberg.org/river/river[river] 0.4+, speaking the stable
`river-window-management-v1` protocol. river owns DRM/KMS, input devices,
rendering, xdg-shell, layer-shell, screencopy, session lock and Xwayland;
oxmonad owns every policy decision: which windows are visible, where they go,
which one has focus, keybindings, borders, and the bar/prompt/tab-strip UI.

Everything oxmonad ships is Rust. river (Zig) is an external runtime
dependency, packaged on Arch as `river`.

== Crates

[cols="1,3"]
|===
| Crate | Responsibility

| `crates/oxmonad-core`
| Pure window-management model. No Wayland, no I/O, no clocks. xmonad's
  `StackSet`, the layout ring, manage rules, the prompt state machine, actions
  and the TOML config schema. Everything here is unit-tested.

| `crates/oxmonad-ui`
| Pure software drawing of the WM-owned surfaces (bar, prompt, tab strip) into
  pixel buffers with `tiny-skia`, `skrifa` and `zeno`. Knows nothing about
  windows or Wayland; takes plain view structs. Golden-image tests live here.

| `crates/river-protocols`
| `wayland-scanner`-generated client bindings for the river protocols
  (`protocols/*.xml`, copied verbatim from river v0.4.8).

| `crates/oxmonad`
| The binary. Connects to river, mirrors river's objects (windows, outputs,
  seats) into core IDs, translates protocol events into core calls and core's
  `Arrangement` into protocol requests, owns the wl_shm shell surfaces the UI
  crate draws into, spawns processes, reads the config file, drives the
  clock/battery bar modules.
|===

Dependency direction: `oxmonad` → `oxmonad-core`, `oxmonad-ui`,
`river-protocols`. `oxmonad-core` and `oxmonad-ui` do not depend on each
other; the binary converts core models into UI view structs.

== The river protocol loop

river drives two kinds of sequences (see the `river_window_manager_v1`
description in `crates/river-protocols/protocols/river-window-management-v1.xml`):

. **manage sequence** (`manage_start` … `manage_finish`): may change window
  management state — dimensions (`propose_dimensions`), `show`/`hide`,
  keyboard focus (`river_seat_v1.focus_window` / `focus_shell_surface`),
  fullscreen, borders, key/pointer bindings.
. **render sequence** (`render_start` … `render_finish`): may change only
  rendering state — node positions (`river_node_v1.set_position`), stacking
  (`place_top`/`place_above`…), decoration offsets, borders.

oxmonad's binary follows one rule: **core state only changes in response to
events; requests are only derived from core state.** Concretely:

* Events outside a sequence (new window, title change, key binding
  `pressed`, pointer op deltas, output added…) are recorded into the model
  and, if they carry user intent (a key press), queued as `Action`s. If an
  action is queued while idle, the binary sends `manage_dirty`.
* On `manage_start`: drain queued actions into core, call
  `Wm::arrange()`, and emit all window-management requests from the
  resulting `Arrangement`, then `manage_finish`.
* On `render_start`: using the dimensions river reported, emit positions and
  stacking for every visible window and shell surface from the last
  `Arrangement`, then `render_finish`. Tiled windows are centred in their
  slot if the client chose a smaller size than proposed.

== Core model (`oxmonad-core`)

Identifiers are opaque newtypes assigned by the binary:
`WindowId(u64)`, `ScreenId(u64)`. Geometry is `Rect { x, y, w, h: i32 }` in
river's logical coordinate space.

=== StackSet

A direct port of xmonad's `StackSet` semantics:

* `Stack<W> { focus, up: Vec<W>, down: Vec<W> }` zipper.
* `Workspace { tag: String, layout: LayoutRing, stack: Option<Stack> }`.
* `Screen { id, workspace, rect, usable_rect }` — `current` plus `visible`;
  remaining workspaces are `hidden`, ordered most-recently-hidden first (drives
  `toggleWS`).
* `floating: HashMap<WindowId, RationalRect>` — floats are stored relative to
  their screen (xmonad's `RationalRect`), so they follow the workspace across
  screens of different size.
* Invariant (tested): every managed window is in at least one workspace; a
  window may be in several workspaces (`CopyWindow`) and is removed from all
  on unmanage. When a copied window is visible on several screens, it is
  placed on the first such screen in screen order and the focused screen
  wins.

=== Layouts

Layouts are pure functions `arrange(&self, area: Rect, n: usize, focus: usize)
-> Vec<Rect>` plus `handle(&mut self, LayoutMessage) -> bool`. The ring from
`resources/xmonad.hs`:

`reflectHoriz tiled ||| tiled ||| Mirror tiled ||| noBorders Full |||
tabbed ||| Mirror Grid ||| Grid ||| ThreeCol ||| reflectHoriz ThreeCol` with
`tiled = ResizableTall 1 (3/100) (3/5) []` and `ThreeCol 1 (3/100) (1/2)`.

Each ring entry keeps its own state; `NextLayout` rotates, `ResetLayout`
rebuilds the ring from config. Messages: `Shrink`, `Expand`,
`IncMasterN(i32)`, `MirrorShrink`, `MirrorExpand`. Integer rounding must
match xmonad (ported from the Haskell sources in `resources/`).

=== Wm facade

`Wm` bundles the `StackSet`, per-window info (`app_id`, `title`,
`has_parent`, fullscreen flag), rules, config-derived settings and the
prompt. The binary talks to core only through `Wm`:

* screens: `add_screen`, `remove_screen`, `set_screen_rect`,
  `set_usable_rect`
* windows: `manage(id, info)` (runs manage rules), `unmanage`,
  `update_info`, `request_fullscreen(id, bool)`, `focus_window(id)`
  (click / pointer focus), `float_at(id, rect)`, `set_float_rect(id, rect)`
* input: `apply(Action) -> Vec<Effect>`; `prompt_key(PromptKey) -> Vec<Effect>`
* output: `arrange() -> Arrangement`, plus view models for the bar
  (`bar_model(screen)`), prompt (`prompt_model()`) and tab strips.
* restart: `snapshot(id_of) -> Snapshot`, `restore(Snapshot)`,
  `manage_as(id, identifier, info)`, `finish_restore()` (see
  <<Restart in place>>).

`Effect` is everything core wants the outside world to do:
`Spawn(String)`, `Close(WindowId)`, `Quit`, `Reload`, `Restart`,
`StartPointerMove(WindowId)`, `StartPointerResize(WindowId)`,
`WarpPointer`… The binary executes effects; core never performs I/O.

`Arrangement` describes the whole desired state:

* `windows`: bottom-to-top list of `Placement { window, screen, rect,
  layer: Tiled | Floating | Fullscreen, border: Option<Border> }` for every
  visible window;
* `hidden`: managed windows to hide;
* `focus`: `Focus::Window(id) | Focus::Prompt | Focus::None`;
* `screens`: per screen its bar rect (if the bar is shown there) and its
  tab strip (rect + tabs) when the layout is `tabbed`.

== UI (`oxmonad-ui`)

Draws premultiplied ARGB8888 (`wl_shm` `argb8888`, little-endian) buffers at
an integer scale. Inputs are plain view structs (`BarView`, `PromptView`,
`TabsView`, `Theme`). Glyph outlines come from `skrifa`, hinted by its
automatic hinter in normal (full) mode so stems snap to whole pixels, with
advances and the pen position rounded to whole pixels; `zeno` rasterizes
them. `[font] antialias` selects grayscale or subpixel (`rgb`/`bgr`,
filtered with FreeType's default LCD filter) coverage; subpixel glyphs are
only drawn in opaque colors over opaque pixels, anything else falls back to
grayscale. The default font is Fira Mono embedded from
`assets/FiraMono-Regular.ttf` (SIL OFL, see `assets/FiraMono-LICENSE.txt`),
so renders are deterministic across machines; a config font family found via
`fontdb` may override it at runtime.

== Configuration

`$XDG_CONFIG_HOME/oxmonad/config.toml`, merged over the defaults embedded
from `crates/oxmonad-core/default-config.toml` (the single source of truth for
default keybindings, colors, commands and rules). `SIGUSR1` (or the
`reload` action) reloads it; `Mod+q` restarts oxmonad, which reads it anew.

== Testing

* `oxmonad-core`: unit tests for the StackSet invariants, every layout's
  geometry, every action, rules, prompt editing and config parsing.
* `oxmonad-ui`: golden PNGs in `crates/oxmonad-ui/tests/snapshots/`;
  regenerate with `OXMONAD_BLESS=1 cargo test -p oxmonad-ui`.
* `oxmonad`: unit tests for arrangement → request translation against a
  recording fake; an `#[ignore]`d end-to-end test runs river headless
  (`WLR_BACKENDS=headless WLR_RENDERER=pixman river -c <oxmonad>`) when
  `river` is installed; another one restarts a copy of the binary in place
  (after replacing it, with it missing, and with `exec` failing) and checks
  the arrangement, pids and open descriptors are unchanged.

== Core implementation notes (deviations)

Where `oxmonad-core` differs from or refines the contract above:

* **Headless state.** xmonad always has a screen; river may start with none.
  Until the first output appears (and after the last one disappears) the
  `StackSet` keeps its current workspace on a placeholder screen that
  `screens()` never reports, so every operation behaves uniformly.
  `Screen` also carries the output `name` (`add_screen(id, name, rect)`), used
  to place the bar (`bar.output`).
* **View semantics.** `view <tag>` (`Mod+1..9`, the prompt) is xmonad's
  `greedyView`, as in xmonad's default keys and `selectWorkspace`;
  `focus-screen` / `toggle-ws` use plain `view`. `view` never creates
  workspaces; the prompt does.
* **Placements.** `Placement.rect` is the window *content* rectangle; the
  border is drawn outside it, so content plus border fill the layout slot
  (xmonad's `tileWindow`). `float_at` / `set_float_rect` also take content
  rectangles. `Full` and `tabbed` place only the focused window; the others
  are listed in `Arrangement.hidden`. `Arrangement` additionally carries
  `prompt: Option<(ScreenId, Rect)>`.
* **Bar model.** There is a single bar, so `bar_model()` takes no screen.
  Workspace order follows `getSortByIndex`: configured tags in config order,
  then the rest sorted by tag. The scratchpad workspace (`NSP`) is excluded
  from the bar, prompt completion, `toggle-ws`, screen assignment and
  `remove-workspace` targets.
* **Copies.** Shifting a window that has copies elsewhere still inserts it
  into the target (xmonad's `insertUp` would silently drop it).
* **Window info.** `WindowInfo` has an optional `preferred_size`, used to
  centre floating transients; without it they take the middle quarter of the
  screen.
* **Effects.** No `WarpPointer` effect: xmonad does not warp by default.

== Binary implementation notes

How `crates/oxmonad` realises the protocol loop above:

* **Modules.** `state` (the mirror of river's objects and the two
  sequences; `state/dispatch.rs` records events), `plan` (pure
  `Arrangement` → request translation behind the `Requests` trait, diffed
  against what river was last told), `shell` + `shm` (bar, tab strips and
  prompt as `river_shell_surface_v1`s in memfd-backed `wl_shm` buffers),
  `keys` / `keyboard` (keysym resolution and the prompt's keyboard via the
  pure-Rust `kbvm`), `status` (clock and battery), `control` (the
  `OXMONAD_CONTROL` socket), `spawn`, `restart` (saving the snapshot and
  re-executing).
* **Shell surfaces are redrawn in the manage sequence**, not the render
  sequence: their content only depends on core state, and committing them
  (with `sync_next_commit`) during the manage sequence maps the prompt before
  river applies `focus_shell_surface`. The render sequence repositions and
  restacks them with the windows.
* **Stacking.** Tiled and floating windows bottom to top, then tab strips and
  the bar, then fullscreen windows (which therefore cover the bar), then the
  prompt.
* **Input ordering.** Key/pointer binding presses, clicks, pointer enters and
  control commands are queued and applied in order at `manage_start`.
  Focus-follows-mouse only acts when the pointer actually moved since the
  previous manage sequence, so re-tiling under a still pointer does not steal
  focus. Pointer bindings act on the window under the pointer.
* **Locking.** While river reports the session locked, only bindings without
  modifiers (media keys) run.
* **Signals** use a self-pipe (`signal-hook`), leaving the signal mask that
  spawned children inherit untouched; children run via `sh -c` in their own
  process group and are reaped on `SIGCHLD` (any exited child, so children
  spawned before a restart are reaped too).

== Restart in place

`restart` (`Mod+q`) replaces the running oxmonad with the binary now at the
path it was started from, keeping every window where it was — xmonad's
`restart`, which serializes the `WindowSet` and resumes it in the new
process.

It relies on three properties of river 0.4.8, verified with a headless
river:

. When the window manager sends `stop`, receives `finished`, destroys its
  objects and disconnects, river keeps running and keeps every window
  alive. Before `finished` river sends `closed` for every window and
  `removed` for every output and seat; oxmonad ignores those.
. A newly bound `river_window_manager_v1` receives `output` (with position
  and dimensions), `seat` and `window` events (with `identifier`, `app_id`
  and `title`) for everything that exists, all before its first
  `manage_start`. `wl_output`s are bound before the window manager, so
  their names are known by then too.
. `river_window_v1.identifier` is stable across window-manager reconnects
  (and unique, never reused).

The sequence:

. Core turns `Action::Restart` into `Effect::Restart`. After the manage
  sequence, the binary runs `<binary> --check-config` (with the original
  arguments); if that fails (binary missing, broken, or an invalid config)
  it logs the error and carries on as if nothing happened.
. It takes `Wm::snapshot` — a serde `Snapshot` (with a `version`) of the
  workspaces in xmonad order with their layout rings (each layout's state),
  window order and focus, which workspace each screen (by output name)
  shows, the current workspace, floating rectangles, fullscreen windows and
  the bar toggle, naming windows by river identifier — and sends `stop`.
. On `finished` it answers pending control commands, destroys every
  window-management object, writes the snapshot to
  `$XDG_RUNTIME_DIR/oxmonad-restart-<pid>.json` and `exec`s the binary path
  resolved at startup (`/proc/self/exe` would point at the replaced, deleted
  inode after a rebuild) with the original `argv` plus
  `OXMONAD_RESTORE=<file>`. The pid stays the same, so river does not
  notice its child exiting; every descriptor oxmonad opens is close-on-exec
  (Wayland socket, epoll, signal self-pipes, control socket, memfds), and
  the new process rebinds the control socket.
. The new process reads and deletes the file (an unreadable or incompatible
  snapshot is logged and ignored), loads the configuration, calls
  `Wm::restore`, binds the window manager and manages the announced windows
  with `Wm::manage_as(id, identifier, info)`: a window the snapshot knows
  goes back to its workspaces, floating or fullscreen, without manage
  rules; others are managed normally. At the end of the first manage
  sequence `Wm::finish_restore` restores each workspace's window order and
  focus and the screens' workspaces (matched by output name, then by
  order), and forgets windows that did not come back.
. If `exec` itself fails after the check passed, the old process restores
  the snapshot into a fresh `Wm` with the configuration reloaded and binds
  the window manager again on its existing connection.

Not preserved: an open prompt, a pointer move/resize in progress, and
xmonad's workspace history beyond the hidden-workspace order. A layout ring
whose layouts changed between the two binaries falls back to the
configured ring (keeping the active layout if it still exists). river keeps
fullscreen windows fullscreen and does not report their dimensions to the
new window manager again, so their size is unknown until they change.
