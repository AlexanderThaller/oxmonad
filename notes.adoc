● Done. Phase 1 visual regression testing is in place and committed.

  What I built

  A headless, deterministic golden-image snapshot harness — the investigation found this is the sweet spot,
  combining two proven approaches:
  - niri's trick: render the real layout + border code with mock windows (solid rectangles), no Wayland clients
  needed.
  - weston's approach: compare against committed reference PNGs.

  How it works (src/snapshot.rs):
  1. Renders solid-color elements with Smithay's software PixmanRenderer — no GPU, no display, identical output
  everywhere → CI-safe and stable.
  2. Reads pixels back via ExportMem::copy_framebuffer.
  3. Encodes/compares against tests/snapshots/*.png with the image crate (small per-channel tolerance; writes
  *.actual.png on mismatch).

  Tests (src/layout.rs): snapshots for 1/2/3-window tiled layouts with focus, driven through the real arrange() +
  border code. The 3-window golden I inspected renders correctly — master left, stack right, focused window
  red-bordered.

  Keeping it lean: renderer_pixman + image are dev-dependencies only, so release binaries don't link them.

  Workflow: just test runs everything (8 tests pass); just update-snapshots regenerates goldens to review as a
  PNG diff in git.

  Key design decision

  Only compositor-drawn output (borders, backgrounds, layout rectangles) is golden-tested — real client content
  (terminal fonts, GPU output) is non-deterministic and would flake. True end-to-end screenshots with real
  clients are Phase 2, via implementing wlr-screencopy (which doubles as a user-facing feature — makes grim work
  against oxmonad).

  Followed AGENTS.md (fmt, clippy clean, Conventional Commit) and saved the testing approach to memory so future
  visual features get snapshots too.

  Where to go next: the resize keybindings (the "Resizable" in ResizableTall), close-window/quit bindings, a
  status bar (waybar — now possible via layer-shell), or Phase 2 wlr-screencopy. Your call.
